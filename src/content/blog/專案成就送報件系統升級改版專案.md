## 概述

<div class="content-lead">
  <p>每年壽險公司都須將保戶的相關資料送件至中央管理的機構作保存備存，以便國家主計處的統計還有，相關理賠資料的國家備份，以保障國家人民的保險讓中央可以記錄與統計。</p>
  <p>此為大型專案：中央統計資料庫接收保險公司資料後，需進行篩選、規範、退回、檢核、正式存進、產生報表等作業。以往多為人工調整，不同險種各有不同方式。本系統將 <strong>10 大產險、8 大壽險、2 共同險種</strong>統一化，建立共同框架模式，並將舊系統整體升級（Cobol 轉 C# 與 SQL）。</p>
</div>

## 過程經歷

### 技術挑戰：大量資料資料庫配置

<div class="experience-block">
  <p>此專案的資料量相當大，Database 容量可能達到 TB／GB 等級，單一 Table 也可能達到數千萬、上億級別。當 Table 過大時，會另外依照時間戳記再建立較小的表，或利用 Group By 將可整合的資料收斂成資料量較小的新表。因此在資料表配置上，多半依<strong>時間</strong>與<strong>公司別</strong>拆分。</p>
</div>

### 技術挑戰：SQL 語法與結構執行效能

<div class="experience-block">
  <p>這個案子是第一次接觸 SQL 語法與資料庫配置、效能等課題。查詢語法上，INSERT／UPDATE／DELETE 相對單純；加索引雖可提升查詢效率，但也會讓寫入變慢。大量資料時應減少使用 CASE WHEN、CURSOR 等逐筆處理的寫法——語法越簡易越好。</p>
</div>

### 技術挑戰：Access 連結 SQL Server 製作 Excel 報表

<div class="experience-block">
  <p>Access 本身也可視為小型資料庫，內部以 VB 為主，連結 SQL Server，將抓取的資料放入 Access 報表後再轉為 Excel 輸出。相關筆記：</p>
  <ul>
    <li><a href="/2020/12/11/access-問題排除舊系統轉新系統">[Access] 問題排除（舊系統轉新系統）</a></li>
    <li><a href="/2021/03/25/portfolioaccess小作品-簡易的sales銷售報表">[Portfolio][Access] 小作品：簡易的 Sales 銷售報表</a></li>
  </ul>
</div>

### 技術挑戰：C# 架構、分工作業配置、NPOI

<div class="experience-block">
  <p>此專案也是第一次以 C# 進行開發，熟悉了 C# .NET WebForm 架構設計，並利用 NPOI 函式庫進行客製化報表開發。→ <a href="/series/csharp">[C#] 程式語言開發</a></p>
</div>

<div class="experience-block">
  <p>在 Git 尚未普及前，許多公司以 SVN 做版控。踏入軟體業後 SVN 已顯過時，但因本升級改版案而實際使用。相關筆記：</p>
  <ul>
    <li><a href="/2019/11/11/版本控管vcs-基礎概念，svn、git比較">[版本控管 VCS] 基礎概念，SVN、GIT 比較</a></li>
    <li><a href="/2019/11/11/subversionsvn-tortoisesvn版控工具">[版本控管] Subversion（SVN）— TortoiseSVN 版控工具</a></li>
  </ul>
</div>

### 技術挑戰：老舊技術 VB、COBOL 翻新成 C#

<div class="experience-block">
  <p>甲方原系統有大量 COBOL 與 VB 程式，伺服器以 AS400 建置。這類舊技術需請教公司資深人員與甲方資深人員後，才理解語意並改寫為 C#。</p>
</div>

### 專案挑戰：原主要人員調職／離職，其餘組員資歷不足

<div class="experience-block">
  <p>此為五年期升級改版專案，時程對軟體界而言相當長，期間技術與人員變動都很大。中途主要人員離職，專案經多人撰寫調整，後續需求變更與 Bug 維修較為棘手。過程中也是第一次接觸 C# 與相關專案，只能盡力快速學習並改進；因學習與改善結構較快，後來才成為小組長。</p>
</div>

### 專案挑戰：系統升級但沒有舊的教學文件保留

<div class="experience-block">
  <p>人員流動大，開發文件多未妥善保留；甲方人員變動亦大，交接常不清楚。原系統架構後續是透過逐一查看與閱讀內容，才逐步理解並翻新到新系統。</p>
</div>
