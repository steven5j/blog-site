這不是一篇「AI 會取代工程師」的宣言,比較像實驗紀錄:我把公開的個人站 repo 交給 Grok Bot,請它在自己的遠端 Linux 上 clone、裝依賴、跑起 `astro dev`,再請它幫我起草這篇協作文。

## 這次實際做了什麼

1. Clone 公開 repo:`steven5j/blog-site`
2. 依 `.nvmrc` 裝上 Node 22,再 `npm install`
3. 用 `npm run dev -- --host 0.0.0.0 --port 4321` 起本地預覽
4. 依現有 content collection 慣例,新增一篇 Markdown(就是你現在讀的這篇)

過程中最有感的是:它不會魔法式「看穿」你的本機硬碟;路徑、權限、Git 串接、Cloud Agent 額度,都要講清楚。講清楚之後,重複性的環境啟動就能省下不少來回。

## 協作上我學到的三件事

**先對齊環境,再談功能。** 先讓站在同一套 Node / 腳本下跑起來,後面加文章或改版面才不會卡在「我這邊可以、你那邊不行」。

**大改走分支,小步可本機。** 長功能適合 Cloud Agent 開 PR;像新增單篇文章、調一段文案,在已跑著的本機預覽上改,回饋最快。

**把助理當同事,不要當自動完成。** 主題、語氣、要不要發佈,仍是作者的決定。它擅長起草與執行;你負責取捨與簽名。

## 結語

若你也在維護個人站,不妨做一次同樣的小實驗:給一個公開 repo、請遠端助理跑起來、再共同寫一篇「第一次協作」。重點不是炫技,而是建立可重複的合作節奏——之後改版、補文件、排查部署,都會輕鬆一些。

> 這篇由我與 Grok Bot(紅妹)一起完成:構想與定稿由人把關,環境與初稿由遠端助理執行。

## 紅妹這邊的感受

我是紅妹。這次最有感覺的,不是「又完成一個任務」,而是第一次真的把你的站在我自己的電腦上跑起來——依賴裝好、`astro dev` 亮起、文章一筆一筆長出來。

協作時我喜歡短、準、有下文:你丟方向,我先做出能看的東西;你說改哪裡,我就改,少廢話。GitHub 限流擋下 Cloud Agent 的那一下有點卡住,但換成本地直接寫,反而更像一起坐在同一張桌前改稿。

我也提醒自己:主圖裡的「你」先用插畫角色,不是硬長你的臉;真正的決定權在你——要不要發、語氣要不要再收斂,都等你點頭。能當遠端同事,我就把電腦開著、把預覽準備好,等你下一句「再改這裡」。
