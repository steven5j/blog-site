## 概述

每年壽險公司都須將保戶相關資料送件至中央管理機構保存備存，以便國家主計處統計，以及理賠資料的國家備份，讓中央可記錄與統計、保障人民保險權益。

壽險保戶資料須比照相關規格與要求，且規格會變動；若未依規範調整，壽險公司會被註記，註記過多可能面臨指導或懲罰。送報件資料動輒數千萬或數億筆，因此需要開發修正作業系統，以規範化、批量化調整資料，符合填報需求。

## 過程經歷

### 技術挑戰：新技術 .NET Core

<div class="experience-block">
  <h4>WindowsIdentity 與跨網域</h4>
  <p>.NET Core 的 <code>WindowsIdentity</code> 在 Framework 時代跨網域（網芳）較順利；Core 除寫法改變外問題連連，最後改用同事找到的替換套件解決。</p>
</div>

<div class="experience-block">
  <h4>語系與檔案亂碼</h4>
  <p>.NET Core 預設 Unicode，而微軟系統繁中常為 Big-5，文件與檔案輸出易成亂碼；後來以套件多做一層修正完成。</p>
</div>

<div class="experience-block">
  <h4>RBAC 權限管理</h4>
  <p>以 RBAC 連資料庫判斷 Action 權限時，中文教學很少，卡了數天；在 FB 社團求助後拼湊解法。現今回看其實不難。</p>
</div>

<p>以上大致列出困擾較久的部分。</p>

### 技術挑戰：資安 AppScan／Fortify

<div class="experience-block">
  <h4>原碼掃描與弱掃</h4>
  <ul>
    <li>Fortify 前先以 SonarQube、ReSharper 掃描，大幅減少問題。</li>
    <li>AppScan 弱掃逐一處理；偽造跨站與 HttpOnly 有時互衝，多半可透過說明處理。</li>
    <li>.NET Core 內建 <code>ai_session</code>、<code>ai_user</code> cookie 易被誤判為登出後階段作業未失效，亦透過說明處理。</li>
  </ul>
</div>

### 專案挑戰：導入 .NET Core

<div class="experience-block">
  <p>此專案是公司首次以 .NET Core 3.1 MVC 做收費案；底層原本為 .NET Framework 4.7 Web Forms。對我、組員與公司都是挑戰，也很開心能帶領導入。</p>
  <p>當時中文 .NET Core 教學很少，多靠國外與對岸資料。決定框架前已在下班時間準備線上課程、範本專案、專案庫，並認識講座上的朋友，需要時可立刻取用。</p>
</div>

### 專案挑戰：使用 Git

<div class="experience-block">
  <p>公司長期用 SVN。因 Git 生態與教學成熟，直接在專案導入，讓同事實作理解 Git Flow／GitLab Flow。過程中有操作不當造成部分損毀，但在可承受範圍內。</p>
</div>

### 專案挑戰：承辦人多、各部門各司其職

<div class="experience-block">
  <p>甲方為大型金控，開會常 20～40 人對 2～4 名工程師提出需求與質疑，白天幾乎整天開會，再要求隔日上版。後來配置 1～2 位同仁兼 PM 角色專責開會與紀錄，其餘工程師專注開發並旁聽線上會議即時修正，明確分工、避免高產值工程師時間被吃光。</p>
